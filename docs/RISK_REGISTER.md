# Risk register

| ID | Risk | Impact | Mitigation | Status |
|---|---|---|---|---|
| R-001 | The active Blackwell server image ships PyTorch 2.5.1 without `sm_120` kernels. | CUDA is reported available but every real kernel fails. | Install the pinned upstream PyTorch/CUDA 13.2 environment and require a compute smoke test, not only `is_available()`. | Mitigated: both `sm_120` GPUs executed BF16 SDPA in the pinned environment. |
| R-002 | The active server initially had a 50 GB data disk while required BF16 files total about 80.02 GB before caches and golden tensors. | A complete split pack cannot coexist on insufficient data disk capacity. | Keep environments/caches separate, download only after a free-space preflight, and require an attached disk that leaves the configured post-download reserve. The first console requests returned `请求参数错误`, but the confirmed capacity change completed after restart. | Mitigated: `/root/autodl-tmp` is now 300 GB with about 299 GB free; both GPUs are available. |
| R-003 | CUDA and Metal RNG streams differ. | False parity failures. | Serialize CUDA-produced initial noise and feed the same tensor to both runtimes. | Planned |
| R-004 | Diffusion VAE relies on CUDA-specific NATTEN/Triton/Blackwell optimizations. | Slow or memory-heavy MLX decode could be discovered too late. | Port the upstream eager 3D-window semantics into bounded MLX SDPA tiles during the early feasibility gate; profile before considering a Metal kernel. | Semantics mitigated: CUDA BF16 reference parity passes; checkpoint-backed tile performance remains active. |
| R-005 | BF16 arithmetic and fused kernels differ across backends. | Small errors can amplify through the sampler. | Compare each block and sampler step; keep safe math until full regression passes. | Open |
| R-006 | LTX-2 Community License applies to model and derivative materials. | Non-compliant public release. | Preserve license and attribution, record modifications, and require legal review before distribution. | Open |
| R-007 | Fine-grained Hugging Face token may lack gated-file permission. | Weight download returns 401/403. | Apply AutoDL `network_turbo`, then perform the no-download metadata probe before starting a transfer. | Mitigated: after the account owner completed Agree and Access, the pinned official gated file redirected to the CDN and returned HTTP 200. |
| R-008 | Pinned upstream commit does not contain the `uv.lock` referenced by the project brief. | CUDA dependency resolution could drift. | Resolve once on the canonical server, archive the generated lock under `golden/manifests`, and use `--frozen` thereafter. | Mitigated: `cuda_uv.lock` is archived and SHA-256 verified. |
| R-009 | Serving, SaaS or duplicate ComfyUI model work could consume core-port effort. | CUDA/MLX parity and local inference would slip or gain conflicting implementations. | Enforce the scope directive and one-way adapter dependency rule; schedule Python API, CLI and ComfyUI only at P7/P8/P9. | Mitigated |
| R-010 | Treating lazy safetensors loading as true out-of-core execution causes repeated page faults during every layer and denoising pass. | Runtime can collapse even if allocation succeeds. | Keep the active component resident; use lazy/sharded loading only to control construction peak and release whole components between phases. | Mitigated |
| R-011 | Stage-two HQ has 32,640 video tokens; an explicit attention-score tensor is quadratic. | Multi-hundred-GB allocation or immediate failure. | Require fused SDPA and prohibit explicit score materialization. The full-shape MLX 0.32.0 probe peaked at Q/K/V/output storage (~1.07 GB), not a score matrix. | Core primitive mitigated; full checkpoint stage integration remains |
| R-012 | A 48-block MLX lazy graph retains large 4096-wide and 4x-FFN intermediates or excessive graph metadata. | Peak memory and compile/evaluation latency grow uncontrollably. | Evaluate at every block in the reference path; compile/group only after peak-memory and parity evidence. The synthetic maximum-shape block released active intermediates at its boundary, and real block-0 checkpoint loading/parity passes at a 773,563,888-byte load peak. | Partially mitigated; live 48-block trace remains |
| R-013 | Gemma, DEV transformer/LoRA and Diffusion VAE remain resident together. | Unified-memory pressure can destabilize macOS despite 128 GB physical memory. | Enforce the stage residency state machine and a configurable system reserve; retain embeddings/latents, not inactive models. | Active |
| R-014 | Reimplementing Gemma 4 from scratch duplicates a fast-moving, already-supported MLX architecture. | Schedule slip and avoidable numerical bugs. | Adapt the pinned MLX-LM Gemma 4 implementation to the exact LTX hidden-state/projection contract and test it against CUDA. | Planned |
| R-015 | MLX compilation captures unresolved lazy file-backed weights or variable pipeline state. | First-run stalls, recompilation, or runtime crashes. | Materialize each active component before compiling stable kernels; do not compile the entire variable-shape orchestration graph. | Planned |
| R-016 | Porting specialized upstream pipelines before canonical HQ generation works. | Scope expansion prevents a usable release. | Limit v1 to canonical HQ T2V, synchronized audio and its optional-image path; defer retake, Dub-It, HDR IC-LoRA, A2V and training. | Mitigated |
| R-017 | AutoDL direct egress can time out before reaching the gated Hugging Face file metadata endpoint. | A failure can be misdiagnosed as missing repository permission. | Apply the provider-documented `/etc/network_turbo` in the Hugging Face shell, then rerun the no-download probe. | Mitigated: accelerated request reaches official endpoint; preserve direct-timeout evidence for diagnosis. |
| R-018 | The official VAE state dictionary is not a direct MLX parameter map: attention QKV is fused, several timestep keys are renamed, decoder gates may require reference folding rules, and `type_emb` is an upstream load artifact. | A generic identity/transpose mapping can silently load an incomplete or numerically different decoder. | Keep explicit version-pinned transform manifests; split QKV, rename timestep parameters, support FP32 gate folding only where the source has gates, and deliberately audit every ignored source. Require exact target-key coverage and CUDA/MLX block parity before checkpoint-backed inference is claimed. | Partially mitigated: the downloaded official VAE header produced a validated 407-target manifest with 144 QKV-split rules and one audited `type_emb` omission. The pinned CUDA loader strict-loads those 407 targets with zero missing/unexpected keys (`vae_cuda_strict_load.json`). The file has no static gate tensors. Full MLX load and checkpoint parity remain active. |
